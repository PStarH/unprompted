Unprompted 是 1.0 之前的原型。修复进入 `main`。没有单独维护的发行分支，没有奖金，也不承诺响应时间。

日常权限见[权限与隐私](permissions.md)。这一页说明怎么报告漏洞，以及什么不能写进公开议题。

## 报告漏洞

使用 [GitHub 私下漏洞报告](https://github.com/PStarH/unprompted/security/advisories/new)。如果那个页面不可用，通过[维护者](https://github.com/PStarH)个人资料上列出的私下方式联系。

不要在公开议题里写利用细节、凭据或私人内容。如果找不到私下渠道，可以开一条很短的议题，只请求一个渠道，不要写技术细节。

请写上受影响的提交、影响、用虚构数据复现的步骤，以及相关的模式或设置。如果涉及真实的 Google 访问、发送开关，或关闭影子模式，请说明。

不要附上 OAuth 凭据、API 密钥、邮件、文档链接或状态文件。

仓库里的政策是 [SECURITY.md](https://github.com/PStarH/unprompted/blob/main/SECURITY.md)。

## 边界

- 服务绑定本机，没有登录。不要用公网主机、反向代理或隧道把它暴露出去。
- 正常模式在你授予写入之前是只读的。显式设置 `UNPROMPTED_SHADOW_MODE=true` 时，影子模式会挡住外部写入。
- `npm run demo` 使用自己的状态，并且只模拟发送。
- 模型的回复不能批准动作、放宽权限，或代替证据。远程模型可以收到你所连接来源里的任务内容。
- 本地状态保存同步来的内容和证据。它不加密。
- 本地文件夹和 Apple 备忘录只在你选定的范围内。Apple 备忘录需要 macOS 的自动化权限。撤销访问会使该来源的证据失效。这不会把工作标成完成。

这些页面里的错误，或普通的产品缺陷，可以发公开议题。用页底的**反馈本页问题**。不要把秘密写进去。
