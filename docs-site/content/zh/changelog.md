## 0.5.1 — 2026-11-17

本版本合并了公开发布的 0.4.x `main` 源码线与 0.5.0 候选，并加入以下经过验证的本地行为。它仍是 1.0 之前的预览；模型签名和真实账号验收仍是另外的工作。

### 安全与授权

- `setup.json` 与 `mcp.json` 中的 OAuth 令牌、模型 API 密钥和连接器凭据在写入磁盘前用 AES-256-GCM 加密。密钥保存在操作系统密钥存储中（macOS 登录钥匙串、Linux secret service、Windows DPAPI）；没有可用存储时退回权限 `0600` 的密钥文件。已有安装会在下次启动时自动加密，不需要重新登录。工作区 SQLite 数据库本身不加密。
- 每个已批准的外部写入都带有绑定任务与效果的密封、一次性授权凭据。账本在派发前边界重新判定，拒绝缺失、被替换或已使用的凭据，批准不会漂移到另一个动作。
- 已派发的发送必须先读回并验证，任务才能完成。仅提供商接受会呈现给模型，但永远不会被视为已完成投递。
- 工作区仅在下一步确实属于用户时把事项列入「需要你」；任务计数包含全部未完成任务，而不只是被列入的事项。

### 可靠性与维护

- 发布验收场景与连接器同步矩阵在浏览器和仓库测试中覆盖六条端到端产品条款。
- 运行时维护周期会清理过期的私有推理会话；只读打开现在要求当前 schema 与 FTS secure-delete，不再静默继续。
- 对账确认没有效果后，非 live 尝试可以重试；已经派发的 live 尝试仍不能以同一标识再次发送。
- 浏览器只保留一份 MCP 预设目录；文档补充 Apple 日历、邮件与联系人的配置和凭据处理。

### 来源与投递

- GitHub 仓库可以选择把签名 webhook 发送到本地接收器。接收器对精确请求体验证 HMAC，检查当前账号和仓库允许列表，并在一个原子操作中写入一条幂等回执；需要拉取时再写入一个持久任务。现有 GitHub 连接器随后执行正常的已授权增量拉取。它从不接受提供方内容、注册钩子、打开隧道或取代轮询。
- 来源健康报告有界的公开失败消息和固定的修复分类；提供方给出重试时间时一并显示。凭据、账号标识、续传令牌和响应正文会被遮蔽。
- 保留已打标签的 0.4.0 源码线，包括零配置的 Apple 日历、邮件和通讯录连接器及其导航浏览器覆盖。

### 模型、令牌与资金控制

- 保存的路由组可以按阶段（解读、发现、规划、验证、通用）选择模型，并可选一个回退模型。回退只限于已分类的提供方瞬时、传输或能力不支持失败；路由不是质量或价格排名，也不能切换提供方凭据。
- 模型设置可以按工作区或任务执行可选的 UTC 每日令牌上限和模型费用上限。`null` 关闭上限；`0` 阻止新的支出。用量报告已结算、已预留和未知金额，缺失的用量或价格绝不当作零。配置的令牌和费用上限通过记账适配器在经典 harness 路径上执行；无法为请求记账的调用路径（尤其是 Pi harness）在配置了相关上限时会被拒绝。
- 自动跟进可以包含单独的一笔有限交易额度，使用一种明确的 USD、CNY 或 EUR 货币，带有累计微单位上限、独立到期时间和明确确认。正上限需要持久原生工作区。付费的平台或 MCP 动作需要一份单独的已确认合约，把精确的金额和货币字段映射到该额度。额度不授予提供方、目的地或工具。
- 无法记账的模型用量和没有独立财务回读的已接受交易保留全额占用为未知；占用不是退款，动作也不会盲目重试。续期、到期、撤销和重启不会重置已花资金或未知占用，也没有自动货币换算。

### 持久执行与工作区

- 持久推理会话、模型提交、规划上下文修订、预算唤醒和有界崩溃恢复在重启后保留执行状态。启动时的重新核对默认最多检查八件按风险排序的开放任务，并报告有多少任务留在了这次扫描之外。
- 受监督的 Experience 试验会用保存的声明式用例评估候选，并可以在现有草稿的当前复核令牌下准备一次有范围的格式试验。试验结果只是建议；采纳只改变规划资格，绝不授予连接器、工具或提供方权限。
- 工作区增加了模型预算/路由控制、来源健康和修复状态、记忆焦点/导航以及任务页面焦点。macOS 应用构建使用包版本作为其 bundle 元数据。
- Notion 分发工作包括本地 broker 后端和面向机密 OAuth 发布者的桌面客户端协议。它尚未部署，也没有注册的发布者身份；自托管 Notion 连接仍然可用。

### 此版本说明的限制

- 轮询仍是每个来源的主要路径。只有 GitHub 有可选 webhook；它是对已授权拉取的延迟提示，不保证送达，其他提供方都没有推送。`/api/stream` 是工作区快照，不是事件流。
- GitHub webhook 需要操作者管理的仓库、只转发 `/api/webhooks/github` 的 HTTPS 端点或反向代理、16–1024 字符的密钥、仓库允许列表，以及已经连接的 GitHub 账号。接收器从不注册钩子或打开隧道。
- 连接健康反映最近一次同步尝试及其分类失败；它不是主动的在线探测。从未同步的来源报告为未知。
- 记忆有效性跟随来源可用性和已存储的来源引用，而不是后续的来源修订。编辑来源文档不会自动使已记住的事实失效。
- 模型路由是有界的按阶段分发配置。它不按质量或价格给模型排名。
- 令牌和费用上限是可选的，配置前关闭。费用是根据用户确认的整数价格估算的；提供方账单可能不同。缺失的价格或用量保持未知，不当作免费。令牌和费用上限与交易额度相互独立。配置了相关上限时，Pi harness 会被拒绝。
- 交易额度不是支付能力，不能承诺提供方侧的硬性银行上限。它不进行货币换算。结果未知时保留占用，不盲目重试。
- 自动观察读取提供方定义的狭窄子集。更广泛的 API 访问需要明确的方法和路径前缀授权。
- 重复工作按提供方事件身份去重。同一事实通过两个提供方观察到时，会通过 Situation 关联，而不会合并成一个事件。
- 应用是一个人、一台机器、一个进程，每个存储一个写入者。它绑定 `127.0.0.1`，没有登录。令牌、模型密钥和连接器凭据在磁盘上加密；工作区数据库不加密。
- 测试使用合成提供方和虚构数据。它们不能证明真实账号行为、真实用户价值、提供方可靠性，也不能证明五分钟的非开发者上手。这个合并候选的托管 CI 尚未执行，Windows 运行时验收仍待完成。
- 本地 macOS 应用产物未签名、未配置描述文件、仅 arm64，且未公证。扩展接口不是稳定的 SDK。
- Notion broker 尚未部署，也没有注册的发布者身份；提供方和安全审查仍是外部门槛。

## 0.4.0 — 未发布

- 面向 macOS 和 Windows 的自托管浏览器工作台；不需要桌面安装包。托管 CI 覆盖 Windows 安装、持久化和浏览器启动。
- 来源权限、有范围的平台动作、增量同步和恢复改进。
- 权限刷新使收窄变更保持只读；产物重试保留原始执行者和复核令牌。邮箱格式、编码路径边界和 Google Docs 回读接受更严格的验证。
- 记忆探索、MCP 连接控制和任务详情导航。
- 当上一个分区变空时，任务分组会自动跟随；你明确选择的分区保持不变。
- 应用包排除本地编辑器备份；隐私文档说明实际的凭据存储和删除限制。
- 来源继续使用周期性对账。实时提供方通知推迟到后续版本。

## 0.3.0

你连接自己的模型，以及你授权的来源。另一套演示用虚构数据走一遍循环：事件、证据、被授权的动作，然后是核验过的结果。

### 第一次运行

- 首页上的来源：本地文件夹、macOS 上的 Apple 备忘录、Google、GitHub、Outlook、Slack 和 Notion。多个来源可以同时启用，不必重启。断开也是各自独立的。
- 用 `npm start` 启动，然后**验证并连接模型**。要先得到一次真实的结构化响应，连接才会保存。密钥不会进入工作区、API 或事件流。
- GitHub 和 Outlook 使用设备授权，并在启用前核对已登录的账号。Google 的同意不用重启即可生效，并读取最近的邮件和已有的 Docs。
- Gmail 和 Outlook 可以保存草稿。Notion 和 Apple 备忘录可以在你另外授权的目的地里创建内容。发送是单独的授权。GitHub 和 Slack 保持只读。
- 中文和英文跟随浏览器语言。默认端口被占用时，启动会打印另一个地址。

### 这一版写明的限度

- 测试使用虚构数据和脚本化的提供商。它们不能证明真实用户价值，也不能证明提供商在生产环境里可靠。
- 一个本地用户，每个存储一个写入者。扩展接口还不是稳定的 SDK。
- macOS 构建器可以产出未签名的审阅包。签名和公证是另外的发布工作。本站不提供这个下载。
- 真正未经请求就发现的工作，仍然是验证的优先事项。
