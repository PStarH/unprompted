# Product direction

Unprompted is a proactive partner for work and life. It notices meaningful
changes in authorized context, identifies useful work, checks evidence and
prepares the next step. A fresh prompt is not required for every task.

## What we optimize for

- Useful discoveries from the user's real environment.
- Little setup, clear source permissions and immediate connection feedback.
- Quiet observation; interruption when a decision actually needs the user.
- Source-backed preparation, explicit authority and verified external outcomes.
- Honest empty results and failures, with a practical way to recover.

Email, documents, local text folders, Apple Notes, assigned GitHub issues,
pull request reviews, repository commits and Actions runs are current sources.
They do not limit the product to one provider or to a single office workflow.
A new connector should explain the real situation it helps, the signal it
observes, and what would justify a useful next step.

## Product boundaries

Models interpret context; the engine owns identity, evidence, authority and
completion. An assigned GitHub issue is a provider fact, not an email. An issue
closed elsewhere is not a verified agent accomplishment. Reading a source does
not authorize sending or modifying it.

The default app connects actual sources. Developer fixtures and the explicit
rule-only example remain useful for reproducible engineering, with their
simulated inputs and outcomes labelled.

## Learning from use

A passing fixture proves an engineering contract. Real value requires a real
person to confirm that an unrequested finding was useful and worth keeping in
their workflow. Report useful, missed and noisy discoveries using synthetic or
redacted reproductions; never post credentials or private workspace records.
See [feedback and validation](VALUE_VALIDATION.md).
