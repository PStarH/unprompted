使用指南

自动跟进

本页目录
  1. 两个不同的开关
  2. 仍然要经过的检查
  3. API

默认仍是一次批准一件事。自动跟进是你自己开启的一段授权。它省掉后面的点击，不跳过证据、权限和回读。

影子模式会藏起这些控件，并拒绝请求。显式设置 UNPROMPTED_SHADOW_MODE=true 会禁止对外写入，连接器仍需要自己的授权。见权限与隐私。

两个不同的开关#

本次发送，今后自动在一份准备好的回复上。它发送这一次，并为该范围记下一条长期约定。设置里的已约定的自动跟进列出这些约定。改为逐次确认结束约定。已经发出的回复不会被撤回。

限时自动跟进是另一套。

  • 这件自动跟进只覆盖一项任务，直到它完成、取消或被放下。重新打开这项任务，不会恢复这段授权。
  • 开启限时自动跟进覆盖当前工作区，包括这段时间里新发现的任务。填写 1–1440 分钟。输入框一开始是 30。你设下的截止时间在重启后仍然有效。

正在生效的授权显示在工作区上方。停止自动跟进会结束它。提供商已经接受的写入不会被撤销。

模型的回复不能创建这两种授权。

仍然要经过的检查#

这段授权可以发送准备好的回复，或应用准备好的文档补丁。它不会打开新的目的地，也不会授予连接器写入。

暂停的任务，或还要再审一遍、还要重新读取的任务，不会自己执行。提供商结果不确定时，任务会显示自动执行已暂停，同一次尝试不会盲目重试。

API#

POST /api/autonomy

json
{ "mode": "time", "durationMinutes": 30 }
json
{ "mode": "task", "taskId": "TASK_ID" }

响应包含 grant 和 state。同一模式、同一任务的新授权会替换上一条。时间授权和任务授权可以同时存在。POST /api/autonomy/GRANT_ID/revoke 停止该授权。GET /api/state 包含 autonomy.enabled 和当前有效的授权。

无效输入返回 400。影子模式下的错误文本是 YOLO requires write mode.
