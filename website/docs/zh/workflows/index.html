使用指南

工作如何推进

本页目录
  1. 一轮处理
  2. 长期目标
  3. 完成指什么

触发来自你授权的来源里的变化。不需要为每一项工作写提示词。

text
事件 → 请求 → 证据 → 准备好的动作 → 你的决定
    → 若已许可则对外执行 → 回读

模型可以解释和起草。身份、权限、审阅令牌、发送和核验由确定性检查负责。模型的回复不能批准动作，也不能把任务标成完成。

一轮处理#

  1. 连接器记录一封邮件、一次文件变化、一个议题或一条备忘录。
  2. 应用在你允许的来源里寻找请求和证据。
  3. 证据缺失或过时，工作就保持打开，不会变成一句听起来确定的回答。
  4. 准备好的回复或补丁出现在 待你处理，证据放在旁边。
  5. 批准使用当前的审阅令牌。来源变了会返回冲突，需要再次审阅。
  6. 如果允许写入，应用会回读提供商的结果。不确定的结果不会盲目重试。

来源上更新的结果，可以撤回还没发出的草稿。口头说一项任务已经处理过，不会生成回执。

长期目标#

长期目标可以在你确认的范围内 观察 或 准备。连接了模型时，准备会使用模型；否则准备一份来源摘要。两者在你审阅之前都留在本地。长期目标不会因此获得普遍的写入权限，即使别处存在某个目的地授权。

记忆页用来创建和暂停目标。工作区显示准备好的草稿和审阅。

完成指什么#

来源上的事项关闭后，就不再跟踪。这不是智能体完成了工作。核验过的结果，要求在一次被允许的动作之后完成回读。npm run demo 可以用虚构数据走一遍这个循环。那不是你的工作区。
