## 处理管线

触发工作的是已授权上下文中的有意义变化，而不是一条新的提示词：

```text
授权变化 → 发现承诺 → 核对证据
        → 准备下一步 → 你决定
        → 外部操作（若获授权） → 回读结果
```

模型负责解释和准备。确定性代码负责来源身份、关联、证据要求、权限、审阅令牌、派发和验证。模型响应不能批准操作，也不能把任务标记为完成。

## 示例：一封邮件请求

1. 一封邮件要求在周五前提供项目更新。
2. 连接器记录邮件。模型识别请求、截止时间和缺失的证据。
3. Agent 在你授权的来源中查找当前项目文档、近期结果和之前的回复。
4. 只有当确实有需要决定的事情时，任务才出现在 **需要你**。详情显示拟议回复、目标、要求清单和证据摘录。
5. 如果发送已授权，批准审阅令牌会派发准备好的回复；否则任务保持已准备、未发送。
6. 派发后，应用回读已接受的消息。只有确认的回读才成为 **已验证**。已接受但未确认的结果会保持可见，并阻止重试。

更新的来源结果可以自动撤回已准备的草稿。缺失或过时的证据会让工作保持打开，而不是生成听起来很确定的答案。

## 示例：GitHub 审阅请求

GitHub 提供分配给你的 issue、审阅请求、近期提交和 Actions 运行。Agent 可以把审阅请求与 issue、变更文件的元数据和失败的检查关联起来，准备一份摘要或审阅回复供你检查。连接器保持只读：不会评论、审阅、合并或重跑工作流。

## 示例：带版本检查的文档修改

对于有来源的文档，Agent 针对它读取的版本准备补丁。批准绑定到来源、负载、版本和目标。如果文档在派发前发生变化，任务返回 `REVIEW_CHANGED`，必须重新审阅。获准写入后，应用会回读文档再报告成功。

## 常驻目标与等待

常驻目标让 Agent 在定义范围内持续准备工作。它可以观察和准备，但不会获得通用的外部写入权限。当进展依赖某个人、来源或外部结果时，会使用持久化等待。等待在重启后仍然存在，并且可以同时解开多个任务。

修正会被记录，而不是被隐藏。如果后续消息替换了早先的承诺，可信修订生效；如果工作被撤回，准备好的操作也会撤回。

## Agent 何时询问

外部操作需要以下之一：

- **单独批准** — 默认。
- **任务 YOLO** — 对一个任务自动批准，直到完成、取消、拒绝或不可用。
- **时间 YOLO** — 对整个工作区自动批准 1–1440 分钟，包括期间发现的新任务。

YOLO 是已保存的用户授权。模型响应或工具参数不能创建它。暂停的任务和指导已变化的任务仍会停下来等待审阅。影子模式拒绝 YOLO 写入。撤销会停止尚未派发的操作，但不能撤销服务商已经接受的结果。

## 成功意味着什么

| 状态 | 含义 |
| --- | --- |
| 已准备 | 下一步和要求已准备好审阅，外部尚未发生任何事。 |
| 等待批准 | 操作有效，但需要人或常驻授权。 |
| 进行中 | 操作已派发，正在处理。 |
| 已接受、未确认 | 服务商接受了某些内容，但尚未回读结果。重试被阻止。 |
| 已验证 | 回读确认了结果。 |
| 失败 | 操作失败，任务带着错误保持可见。 |
| 等待 | 进展依赖某个人、来源或外部结果。 |
| 完成 | 所有要求已满足，没有后续工作。 |

空结果是有效结果。来源关闭只会停止跟踪，不会创建已验证的完成。
