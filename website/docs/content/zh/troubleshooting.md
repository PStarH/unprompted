## 先确认事实

运行失败的命令并读完整个错误。确认基础环境：

```sh
node --version
npm --version
pwd
node --check server.js
npm run check:syntax
```

应用会在 **Ready** 后打印确切 URL。使用该 URL，包括端口。服务器只运行在启动它的机器上。

## 常见问题

| 现象 | 处理 |
| --- | --- |
| 找不到 `node` 或 `npm` | 安装 Node.js 20+（建议 22+），重开终端，运行 `node --version`。 |
| `ENOENT` 或找不到 `package.json` | 进入克隆或解压后的项目目录。 |
| 4173 端口被占用 | 启动器会选择其他端口并打印。显式请求被占用的端口会给出提示：`npm start -- --port 4180`。 |
| 工作页没有内容 | 确认模型与至少一个来源已连接。检查实际读取数量，在连接页选择 **立即检查**。零发现可能是有效结果。 |
| 模型验证失败 | 检查基础 URL、确切模型 ID、密钥和服务商兼容性。验证使用真实结构化请求；失败时保留原连接。 |
| 模型正忙 | 已有模型请求在运行。等待；设置返回 `MODEL_BUSY`。 |
| 模型设置只读 | 环境管理的配置返回 `MODEL_ENV_CONFIGURED`。修改启动环境，而不是界面。 |
| `.env` 不生效 | `npm start` 不加载 `.env`。使用 `node --env-file=.env server.js` 或导出变量。 |
| Google 没有事件 | 确认授权完成、API 已启用、测试用户有效，并检查轮询或 **立即检查**。增量同步只覆盖当前窗口。 |
| Google 授权失败 | 使用 **桌面应用** OAuth 客户端，而不是 Web 客户端。检查已启用 API 和测试用户。 |
| Google 刷新失败 | 令牌可能过期或被撤销。重新授权；测试模式刷新令牌可能七天后过期。 |
| Google 发送被拒绝 | 发送需要 `gmail.send`、`GOOGLE_SEND_ENABLED=true`、关闭影子模式、批准或常驻授权，以及回读。阅读和草稿仍可用。 |
| Outlook 增量失败 | 检查点可能过期。Unprompted 会重新枚举收件箱，不再受初始三天限制，并对已知消息去重。若持续失败，重新连接。 |
| OAuth 回调失败 | 使用确切回环地址：`http://localhost:53682/oauth/slack` 或 `http://localhost:53682/oauth/notion`。端口必须空闲。 |
| `STATE_LOCKED` | 另一个正常模式进程占用了该状态文件。停止它，或换一个状态文件和端口。不要删除活动锁。 |
| 浏览器无法连接 | 使用打印的 `http://127.0.0.1:PORT/`。另一台机器或容器中的服务器需要明确可达的地址。 |
| `WORKSPACE_CONNECTING` | 连接转换正在进行。等它完成再重试。 |
| `REVIEW_CHANGED` | 审阅准备后来源、指导或目标变化。获取当前任务并重新审阅。 |
| `DURABLE_WORKSPACE_REQUIRED` | 此变更需要持久工作区。不要在临时演示中尝试。 |
| 找不到 MCP 工具 | 安装 `npm ci --include=optional`，重启，检查服务器状态。没有注解的工具需要显式读取授权；可写或破坏性工具保持阻断。 |
| MCP 资源不可用 | 在 **资源与访问** 中选择资源。仅支持文本；暂不支持模板和订阅。 |
| 来源暂停或断开 | 重新连接并检查服务商状态。断开的来源不能提供当前证据；旧工作不算完成。 |
| 应用显示未知或未确认 | 这是真实状态，不是 bug。没有回读的外部操作会保持阻断，直到对账。不要盲目重试。 |

## 在不暴露数据的情况下检查状态

```sh
curl http://127.0.0.1:4173/api/health
curl http://127.0.0.1:4173/api/runtime
curl http://127.0.0.1:4173/api/state
```

这些接口只在本机、无身份验证。不要暴露端口。分享输出前删除账号名、消息内容、文档文本、令牌、密钥和文件路径。

## 安全重置

- **演示：** 停止后再次运行 `npm run demo`。临时工作区可以丢弃。
- **正常模式：** 先停止进程。需要历史时先备份状态文件。第二个实例使用不同的 `UNPROMPTED_STATE_FILE` 和端口。
- **凭据：** 撤销或轮换服务商授权，然后删除本地设置条目。只删除本地状态不会撤销服务商令牌。
- **模型：** 断开或替换连接。替换失败不会覆盖之前可用的连接。

进程运行时不要删除锁文件。如果进程崩溃且你确定没有实例在运行，把状态和锁一起移走，再重启。

## 何时提交 issue

包括：

- 操作系统与架构；
- Node.js 与 npm 版本；
- 确切命令和打印的地址；
- 错误文本或 API 状态码；
- 工作区是演示还是正常模式；
- 连接器名称，以及使用真实账号还是脚本账号。

不要包含凭据、令牌、真实邮件或文档内容、状态文件和私有路径。使用仓库的 issue 模板：
[提交 bug](https://github.com/PStarH/unprompted/issues/new/choose)。
